# 图片存储规范

网站图片统一存放在 `static/images/`，公开地址为 `/images/`。

- `static/images/<文章 slug>/`：一篇文章一个目录，与该文章实际网址的最后一段一致。没有显式 slug 时，以 Hugo 实际生成的网址为准。英、日译文共用中文原文的目录。
- `static/images/site/`：网站共用图片，包括 Logo、头像、首页图片、默认分享图及关于页、数字名片共用图片。
- `static/images/shared/`：多篇不同文章共用的图片，只保留一份。
- `static/images/` 根目录：尚未使用或暂时无法归属的文件，保留原文件名，暂不删除。

遗址、私人记录等独立内容页也按各自网址分目录。文章改标题时不需要改图片目录。新增图片尽量采用含义明确的文件名；本次整理保留历史文件名、格式及文件内容。

修改位置时，应同时更新正文、各语种封面、页面元数据、站点配置、模板、样式及 Hugo Pipes 中的资源路径。不要手工修改 `public/` 和 `resources/` 中的生成文件。

## 季节主题

四季 Hero 与 Logo 使用 `static/images/site/zisai_hero_<season>.webp`、`zisai_logo_<season>.webp`。在 `hugo.toml` 的 `[params.zisai]` 中，通过 `heroImage`、`logoImage` 两项统一切换；当前使用 `winter` 冬季组合，不按日期自动切换。Logo 的顶部导航、首页关于卡片和数字名片共用同一配置。

## 自动图片优化

正文中的 Markdown 图片和文章页封面自动生成 480、768、960、1440、1920 像素宽的 WebP 候选图，质量参数为 85；只生成不超过原图宽度的尺寸，小图也会生成原尺寸的 WebP，不会放大。浏览器通过 `srcset` 按显示宽度和屏幕像素密度选择。正文图片延迟加载，文章封面优先加载，并设置图片宽高以减少布局跳动。

首页背景也生成 WebP，数字名片照片提供 144、288、432 像素候选图；列表缩略图和 Logo 保留各自适用的小尺寸。外链图片、SVG、GIF、APNG 和动态 WebP 不做上述转码。用于社交分享和结构化数据的原始图片地址仍保留。

Hero 背景按屏幕宽度单独选图：760px 及以下使用 960px 宽、质量 78 的手机版，761–1320px 使用 1280px 宽、质量 80 的平板版，更宽屏幕使用最大 1920px 宽、质量 82 的桌面版。均不放大原图。CSS 媒体查询和图片预加载使用相同断点，避免手机提前下载桌面大图。图片比例及原有背景定位保持不变。

原图继续放在 `static/images/`，自动生成的 `_hu_*.webp` 是构建产物，由 Hugo 缓存并发布，不能当作未使用原图清理。首次生成需要较长构建时间。

`scripts/organize_images.py` 用于生成迁移计划、执行迁移和核对图片完整性；自动归属结果须先人工检查。它不删除未使用文件，也不生成图片地址重定向。

核对本次图片完整性（第二个位置参数仅用于保持命令接口，verify 模式不读取文章清单）：

```powershell

```

以后新增或替换图片后，这份历史清单自然不再与全量目录一致；应按新的变更范围核对。

## 原创图片水印

水印由站点模板实现。`[params.watermark]` 是紫塞网配置，Hugo Pipes 用原图生成带文字的 WebP。默认文字为 `© ZISAI.COM`，右下角、30% 不透明度。输出的短边不足 400 像素时跳过。`position` 支持 `bottom-right`、`bottom-left`、`top-right`、`top-left`。缩放与文字合成在一次 WebP 编码内完成。Hugo 按源图、处理参数和滤镜缓存结果。

先确认图片权属和署名，再启用。默认未获批准的图片保持现有输出。确认整篇文章的适用图片均可标记时，在 front matter 添加：

```yaml
watermark:
  enabled: true
  images:
    "photos/visitor-photo.webp": false
```

只批准个别图片时省略 `enabled`，将对应路径设为 `true`。键使用小写路径，去掉开头的斜线和查询参数。静态图填写 `images/文章目录/文件名.webp`，相册填写 `photos/文件名.webp`。设置文章 `enabled: false` 可排除整篇。`watermark.text` 可指定经权利人同意的文字。画廊摄影者仍由 `galleryPhotographer` 独立署名。

在 `[params.watermark.categories]` 中可按分类名批准或排除，键使用小写。分类批准适用于该分类下的整个图片集合，仅在权属清楚时启用。文章、分类或图片中任何显式排除都优先。技术分类、站点与共享素材目录、常见 Logo／吉祥物／头像／二维码／截图命名受保护。命名规则无法识别所有视觉内容，混合来源文章应逐图批准。

覆盖 Markdown 图片、使用现有封面和列表缩略图模板的图片、画廊缩略图及灯箱。Page Bundle 和已挂载为 assets 的 `static/images` 本地图可参加处理。原图继续保留，现有静态路径仍可访问。远程图片、SVG、动态图片、硬编码 HTML 或 CSS 图片、视频和 SEO／分享图继续使用现有路径。Raw HTML 图片可在逐页审核后改用 Markdown 或现有封面入口。若以后要让指定原图仅留在源仓库，需逐批审查旧引用和公开 URL，再迁入仅供 Pipes 使用的 assets 或专用 Page Bundle，并用独立构建校验。现有路径不做批量迁移。

回滚时把 `[params.watermark]` 的 `enabled` 改为 `false`，用干净输出目录重新构建。页面会恢复使用原有衍生图或灯箱原图。
