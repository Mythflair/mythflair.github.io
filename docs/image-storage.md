# 图片存储规范

网站图片统一存放在 `static/images/`，公开地址为 `/images/`。

- `static/images/<文章 slug>/`：一篇文章一个目录，与该文章实际网址的最后一段一致。没有显式 slug 时，以 Hugo 实际生成的网址为准。英、日译文共用中文原文的目录。
- `static/images/site/`：网站共用图片，包括 Logo、头像、首页图片、默认分享图及关于页、数字名片共用图片。
- `static/images/shared/`：多篇不同文章共用的图片，只保留一份。
- `static/images/` 根目录：尚未使用或暂时无法归属的文件，保留原文件名，暂不删除。

遗址、私人记录等独立内容页也按各自网址分目录。文章改标题时不需要改图片目录。新增图片尽量采用含义明确的文件名；本次整理保留历史文件名、格式及文件内容。

修改位置时，应同时更新正文、各语种封面、页面元数据、站点配置、模板、样式及 Hugo Pipes 中的资源路径。不要手工修改 `public/` 和 `resources/` 中的生成文件。

## 自动图片优化

正文中的 Markdown 图片和文章页封面自动生成 480、768、960、1440、1920 像素宽的 WebP 候选图，质量参数为 85；只生成不超过原图宽度的尺寸，小图也会生成原尺寸的 WebP，不会放大。浏览器通过 `srcset` 按显示宽度和屏幕像素密度选择。正文图片延迟加载，文章封面优先加载，并设置图片宽高以减少布局跳动。

首页背景也生成 WebP，数字名片照片提供 144、288、432 像素候选图；列表缩略图和 Logo 保留各自适用的小尺寸。外链图片、SVG、GIF、APNG 和动态 WebP 不做上述转码。用于社交分享和结构化数据的原始图片地址仍保留。

原图继续放在 `static/images/`，自动生成的 `_hu_*.webp` 是构建产物，由 Hugo 缓存并发布，不能当作未使用原图清理。首次生成需要较长构建时间。

`scripts/organize_images.py` 用于生成迁移计划、执行迁移和核对图片完整性；自动归属结果须先人工检查。它不删除未使用文件，也不生成图片地址重定向。

核对本次图片完整性（第二个位置参数仅用于保持命令接口，verify 模式不读取文章清单）：

```powershell
python scripts/organize_images.py unused docs/image-migration-2026-10-24.json --verify
```

以后新增或替换图片后，这份历史清单自然不再与全量目录一致；应按新的变更范围核对。
